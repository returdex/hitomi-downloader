# Quick Task 260504-002: Research

## Findings

- The current app already has a `HitomiClient.get_comic(id)` path and a `DownloadManager.create_download_task(comic)` path.
- Download destinations are derived inside `DownloadTask::new` from global config `download_dir` plus `dir_fmt`.
- Tauri's dialog plugin is already installed and used for selecting export directories.
- `regex-lite` and `reqwest` are already available in Rust dependencies, so parsing E-Hentai gallery links and fetching the favorites page does not require new packages.

## Approach

- Add a backend command that accepts `cookie`, `favorites_url`, `download_dir`, and optional `limit`.
- Fetch the E-Hentai favorites URL with the pasted cookie header.
- Parse gallery ids from `/g/{id}/{token}/` links, deduplicate them, optionally cap by limit.
- For each id, use `HitomiClient.get_comic(id)` and queue it through the existing download manager.
- Extend the download manager with an optional base download directory override so import-specific downloads do not mutate global config.

## Pitfalls

- E-Hentai favorites HTML can change. Parsing direct gallery links is intentionally simple and robust, but this MVP does not crawl additional favorites pages.
- Some E-Hentai gallery ids may not resolve on Hitomi; these are counted as failed and logged without blocking the whole import.
- Cookie text is sensitive, so it must remain frontend state only and must not be saved to config or planning artifacts.
