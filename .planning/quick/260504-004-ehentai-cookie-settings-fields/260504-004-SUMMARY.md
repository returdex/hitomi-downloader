# Summary

Moved E-Hentai cookie recording into Settings with individual fields:

- `ipb_member_id`
- `ipb_pass_hash`
- `igneous`

The Search pane no longer accepts a full Cookie header. It now points users to Settings and composes the Cookie header from saved fields during manual import. Startup auto-check uses the same helper.

Existing configs with the previous full `ehentaiCookie` value are migrated by splitting out these three fields when possible.

## Verification

- `cargo check` passed with the existing `LoginResp` dead-code warning.
- `pnpm.cmd build` passed after running outside the sandbox so Vite/esbuild could spawn its child process.
- Vite reported the existing non-blocking large chunk warning.

## Security Note

The three cookie fields are still saved in the app config file, not an encrypted OS keychain.
