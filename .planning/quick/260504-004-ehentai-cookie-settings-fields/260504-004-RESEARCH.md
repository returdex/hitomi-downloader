# Quick Task 260504-004: Research

## Findings

- The app already persists config deeply through `AppContent.vue`, so Settings fields can bind directly to `store.config`.
- Search and startup checks both need the same Cookie header construction.
- `utils.ts` is the smallest shared location for a frontend helper used by `SearchPane.vue` and `AppContent.vue`.
- Rust config uses `serde(rename_all = "camelCase")`, so fields such as `ehentai_ipb_member_id` become `ehentaiIpbMemberId` in TypeScript.

## Approach

- Replace the full `ehentai_cookie` config field with `ehentai_ipb_member_id`, `ehentai_ipb_pass_hash`, and `ehentai_igneous`.
- Add a Settings collapse section for E-Hentai Cookie fields.
- Add `buildEhentaiCookie` and `hasEhentaiCookie` helpers.
- Remove the full cookie input from Search pane and show a settings hint instead.

## Pitfalls

- Existing config files may still contain the older `ehentaiCookie` property. Serde ignores unknown fields, and new fields are backfilled by merge defaults.
- `igneous` can be empty for some E-Hentai accounts, so the required check uses `ipb_member_id` and `ipb_pass_hash`.
