<threat_model>
## Security Threat Model

No new authentication, storage model, network endpoint, or secret-handling behavior is introduced by this plan. The primary security-sensitive constraint is to avoid leaking E-Hentai cookie values or filesystem paths in new user-facing messages.

- **Threat:** Error notifications accidentally expose cookie fields or sensitive config values.
  - **Severity:** medium
  - **Mitigation:** Use existing `CommandError.err_title` / `err_message` patterns only where already user-facing, and do not interpolate cookie values or raw config objects into new messages.
- **Threat:** Broad error handling hides actionable failures behind generic text.
  - **Severity:** low
  - **Mitigation:** Preserve console logging for developer diagnostics while adding concise user-facing feedback for direct actions.
</threat_model>
